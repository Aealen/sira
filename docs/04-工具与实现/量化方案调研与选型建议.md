# 量化交易方案调研与选型建议

> 归档日期：2026-09-22
> 类型：调研报告（服务于 SIRA 设计决策）
> 调研问题：①现存量量化方案有哪些？②各自优劣？③SIRA 是否有必要引入量化工具辅助决策？

## 一、调研背景

用户在工具定位对齐阶段提出本调研，并给出关键观点：**"A股 T+1 的特殊性，可以针对不同市场做不同策略"**——该观点正确且直接影响 SIRA 设计：市场规则（T+1/T+0、涨跌幅限制、费率）必须**参数化**，不能写死在策略里。

## 二、现存方案总览

### 2.1 开源框架（本地部署，写代码用）

| 框架 | 定位 | 优势 | 劣势 |
|---|---|---|---|
| **Backtrader** | 回测 + 简单实盘 | 最易上手，社区资源最丰富（GitHub 20K+ star），文档教程多 | 维护活跃度下降，API 风格老旧，A股 T+1/涨跌停需自行改造 |
| **vn.py (VeighNa)** | 国内实盘交易系统 | 国内交易接口最全（CTP 等），事件驱动贴近实盘，金融机构用户多 | 面向期货/实盘为主，重在"交易网关"，回测研究能力一般；对 SIRA 这类不接实盘的项目过重 |
| **Qlib（微软）** | AI 量化投研 | 机器学习因子挖掘能力最强，学术前沿 | 定位投研平台而非交易工具，学习曲线陡，依赖重 |
| **NautilusTrader** | 高性能回测/实盘 | Rust 核心、低延迟、事件驱动、设计现代 | 学习曲线陡，社区偏加密货币/外汇场景 |
| **vectorbt** | 向量化极速回测 | 参数扫描速度极快，适合大规模策略实验 | API 研究向，代码可读性差，新手不友好 |
| **backtesting.py** | 轻量单标的回测 | API 极简，几十行可跑通，可视化好 | 只支持单标的，多标的组合/调仓支持弱 |
| Zipline / QUANTAXIS / ABU 等 | 历史方案 | —— | 维护停滞或社区萎缩，不建议新项目采用 |

### 2.2 在线量化平台（托管数据 + 回测 + 部分实盘）

| 平台 | 优势 | 劣势 |
|---|---|---|
| **聚宽 JoinQuant** | 文档最好、社区最活跃、数据质量高、在线回测方便 | 个人实盘需合作券商；回测资源有限制；对个人定价不友好（基础版约 299 元/月）；商业重心已转向数据服务与自有私募 |
| **米筐 RiceQuant** | 数据专业，开源了本地引擎 RQAlpha | **已取消个人服务**，转向企业方案 |
| **掘金量化** | **支持实盘**（托管/自营账户），实盘门槛低（约 5 万） | 需装客户端，部署较麻烦，社区不如聚宽 |
| **BigQuant** | 可视化 + AI 工具，零编程可上手 | 对程序员灵活性受限，偏研究数据领域 |
| **QuantConnect（LEAN 引擎开源）** | 引擎完全开源可本地部署，覆盖全球市场 | 不支持 A 股行情与实盘；中文资料少；云端付费不便 |

## 三、SIRA 是否有必要引入量化工具？——分四层结论

SIRA 当前定位：**辅助决策工具**（数据 → 指标 → 人决策 → 模拟盘），自建架构 FastAPI + Vue + akshare + SQLite。按功能层次逐层判断：

| 层次 | SIRA 需要吗 | 结论与理由 |
|---|---|---|
| **指标计算库**（波动率/回撤/夏普/分位） | ✅ 需要（M2） | **自研，不引入框架**。总计一两百行纯函数，公式已在知识库 02 归档；自研保证"每一行都看得懂"，这本来就是项目的学习目的。可对照 empyrical 的定义校验 |
| **回测引擎** | 🔶 二期可选 | **建议自研轻量回测，不引入 Backtrader 等重型框架**。理由：① SIRA 模拟盘（M3）的撮合/费率结算逻辑与回测天然复用，自研边际成本低；② 我们要做"市场规则参数化"（A股 T+1 vs 港美 T+0、10%/20%/无涨跌停）——通用框架对此支持都要魔改，反而自研更顺；③ 教学价值是项目目标之一。可选做交叉验证：用 backtesting.py 对照同一策略结果，防止自研引擎有 bug |
| **实盘交易框架**（vn.py） | ❌ 不需要 | SIRA 只做模拟盘，不接实盘（可预见的范围内）；vn.py 的核心价值（券商网关）对我们无用，引入只增加复杂度 |
| **多因子/AI 平台**（Qlib、BigQuant） | ❌ 过度 | 远期有兴趣再议，当前阶段是杀鸡用牛刀 |
| **在线平台**（聚宽等） | ❌ 不作为基座 | 数据与策略锁在平台、月费、与"自建学习工具"定位冲突。**但聚宽的免费额度和文档可作为学习参考读物**（它家的策略教程质量高） |

### 核心结论

**引入"量化思想"（规则化、可回测、纪律执行），不引入"量化框架"。** SIRA 的差异化价值恰恰是"每个零件自己造、每个数字自己算"；重型框架解决的是"成熟团队快速上线"的问题，不是我们的问题。

## 四、对 SIRA 设计的直接输入（本次调研的落地项）

1. **市场规则参数化**（用户 T+1 观点的落地）：在 `config.py` 增加市场规则表——
   `t_plus`（A股1 / 港美0）、`price_limit`（主板10% / 创科20% / 港美无）、费率模型（已有）。
   模拟盘撮合与未来的策略/回测都读这张表。
2. **二期回测引擎的最小形态**（自研）：`历史数据循环 + 策略函数 + 撮合结算（复用 M3）+ 绩效指标（复用 M2）`，不追求通用性，只服务自己的策略。
3. **对照验证工具**：可选引入 `backtesting.py`（极轻）用于回测结果交叉校验。

## 五、SIRA 量化含量决策框架（已拍板）

> **决策记录（2026-09-22，用户确认）**：SIRA 定位 = **辅助决策支撑工具**——只做模拟盘，永不接入真实交易。量化含量以 **A 档（纯辅助）为一期目标**；B 档（回测验证）与 C 档（规则提醒，只提醒不下单）均与该定位兼容，作为二/三期可选项按需推进；**实盘/真实下单方向永久排除**。

"是否引入量化"不是一个是/否问题，而是**含量档位**问题。三档定义：

| 档位 | 内容 | 对应里程碑 | 适合的心态 |
|---|---|---|---|
| **A. 纯辅助** | 指标客观化 + 模拟盘 + 定投计划（现状计划，M1–M5） | 一期完成即达成 | "我先学会看懂市场和管住自己" |
| **B. +验证** | A + 轻量回测引擎：把规则放到历史数据上验证（自研，复用 M2 指标 + M3 撮合） | 二期 | "我想知道我信的规则在历史上靠不靠谱" |
| **C. +信号** | B + 规则提醒引擎：估值分位/再平衡阈值触发买卖提醒（只提醒，不下单） | 三期可选 | "我想让纪律自动盯着，我拍板执行" |

**价值排序的诚实认知**（为什么建议从 A 起步、B 为目标、C 谨慎）：

1. 个人量化策略**大概率跑不赢宽基定投**——这是统计现实而非丧气话；机构在速度、数据、模型上全面碾压个人，个人的优势恰恰是"不需要每年跑赢 benchmark 的业绩压力"。
2. 因此量化对个人的真实价值排序是：**纪律执行 > 认知深化 > 超额收益**。把追涨杀跌的手管住、把"为什么买"变成可验证的规则，比多赚两个点现实得多。
3. 警惕"回测幻觉"：B 档的价值是**证伪**（发现规则不靠谱）多于证实（证明规则赚钱）——抱着这个心态做回测才不会掉进过拟合。
